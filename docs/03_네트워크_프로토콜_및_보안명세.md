# 03. 네트워크 프로토콜 및 보안 명세

## 1. 포트 및 프로토콜 상수
정의 파일: [ProtocolConstants.cs](../src/LabPet.Shared/Protocol/ProtocolConstants.cs)

| 상수 | 값 | 용도 |
| --- | --- | --- |
| `CurrentProtocolVersion` | `3` | 친구 등록 키 합의, 서명된 ACK, 탐색 후보 검증 |
| `MinSupportedProtocolVersion` | `3` | v1·v2는 제어 연결 거부 및 업데이트 필요 판정 |
| `UdpDiscoveryPort` | `45678` | LAN 피어 탐색(`HELLO`) 브로드캐스트 |
| `UdpMusicFramePort` | `45679` | 30Hz 노래 따라하기 오디오 프레임 유니캐스트 |
| `TcpControlPort` | `45680` | 친구 신청/수락, 말풍선 메시지, 노래 따라하기 구독 제어, 친구 코인 게임 이벤트(`PacketType.GameEvent`) |
| `MusicHostSilenceTimeoutMs` | `180000` | 노래 따라하기 호스트 완전 무음 시 자동 해제 기준(3분) |
| `MusicFrameTimeoutMs` | `15000` | 노래 따라하기 UDP 프레임 미수신 시 로컬 모드 복귀 기준(15초) |

## 2. 프로토콜 버전 호환성 정책
- `peerProtocolVersion < MinSupportedProtocolVersion` → `PeerOutdated` (상대 업데이트 필요)
- `peerProtocolVersion > CurrentProtocolVersion` → `LocalOutdated` (로컬 업데이트 필요)
- 호환 범위를 벗어난 피어의 TCP 제어 연결은 닫는다. 미등록 피어의 탐색 목록에는 호환 상태를 표시한다. 등록된 구버전 친구는 모두 업데이트하기 전까지 인증된 온라인 상태로 표시되지 않는다.

## 3. 친구 인증, AES-256-GCM 암호화 및 로컬 비밀키 보호
정의 파일: [PacketSigner.cs](../src/LabPet.Shared/Protocol/PacketSigner.cs), [PacketCrypto.cs](../src/LabPet.Shared/Protocol/PacketCrypto.cs), [Packets.cs](../src/LabPet.Shared/Protocol/Packets.cs), [LocalSecretProtector.cs](../src/LabPet.Client/Storage/LocalSecretProtector.cs)
- 수신자가 수락하면 두 앱은 임시 P-256 ECDH 공유값과 HKDF-SHA256으로 확인 키와 장기 친구 키를 각각 파생한다. 신청 ID, 양쪽 펫 ID와 공개키, 신청 본문이 파생에 묶인다. 두 앱은 공개키와 확인 서명을 교환하며 장기 친구 키는 로컬에서 생성한다. 신청의 유효 시간은 3분이다. [친구 등록](../src/LabPet.Client/Network/LanP2pTransport.Pairing.cs)
- 최초 등록에서 키 확인은 양쪽이 같은 키를 합의했는지 검증한다. 상대의 신원을 독립적으로 확인하는 단계가 없으므로 최초 등록 중 능동적 중간자 공격에 대한 방어는 제공하지 않는다.
- 신청자는 현재 대기 중인 신청과 수락 서명을 검증한 뒤 등록한다. 수락자는 확인 키로 서명된 ACK를 확인한 뒤 등록한다. 같은 신청의 확인 재시도는 등록 이벤트를 다시 발생시키지 않는다. 이미 등록된 친구의 키는 새 요청으로 교체하지 않는다. 업데이트 시 기존 DPAPI 키를 계속 사용하므로 구버전에서 이미 유출된 키는 업데이트만으로 교체되지 않는다.
- 친구 제어 패킷은 AES-256-GCM 암호화와 HMAC-SHA256 서명을 요구한다. ACK는 송신 메시지 ID, 상대 ID, 프로토콜 버전 및 인증 키와 연결한다. 암호화되지 않은 탐색 HELLO는 검증 후보로만 사용하고, 인증된 TCP 프레즌스 교환 뒤에 친구 IP·포트·이름·외형과 온라인 상태를 갱신한다. [TCP 제어](../src/LabPet.Client/Network/LanP2pTransport.Control.cs), [프레즌스 검증](../src/LabPet.Client/Network/LanP2pTransport.Presence.cs)
- TCP는 시각 오차 ±2분을 허용하고 친구별로 최대 1,024개 요청 ID와 처리 결과를 메모리에 보관한다. 내용이 같은 요청을 다시 받으면 같은 결과를 응답하며, 상태 변경은 한 번 실행한다. 앱을 완전히 재시작하면 메모리 재전송 기록은 초기화된다. UDP 음악은 HMAC 검증 후 구독 ID와 송신 순번을 확인한다. [재전송 검증](../src/LabPet.Client/Network/ControlReplayWindow.cs)
- TCP 수신은 16개 워커와 연결별 4초의 비동기 제한 시간을 사용한다. 기본 포트 충돌 시 LAN 연결이 시작되지 않으며 환경 안내를 표시한다.
- `friends.json`과 정상 JSON 백업의 키는 현재 Windows 사용자 계정의 DPAPI로 보호한다. 평문 백업도 변환한다. DPAPI에서 읽을 수 없는 암호문은 보존하고 원래 사용자 계정에서 복구하도록 안내한다. 본 파일과 백업이 모두 읽히지 않으면 덮어쓰지 않는다. [친구 저장소](../src/LabPet.Client/Storage/JsonAppDataStore.cs)

## 4. LAN 게임의 신뢰 범위

- 가위바위보는 양측이 난수를 포함한 선택 해시를 먼저 교환하고, 공개된 선택이 해시와 일치할 때만 정산한다. 상대가 공개를 중단하면 시간 제한 후 미완료 로컬 라운드의 코인을 반환한다.
- 타이핑 결과는 상대가 보낸 점수 대신 세션 문장과 제출 기록으로 재계산한다. P2P에서는 사람이 입력했는지 또는 자동화가 입력했는지 판별할 수 없다.
- 사다리 게임은 초대 응답 완료 후 방장의 참가자 확정, 중복 없는 시작 위치 선택 완료, 방장 PC의 암호학적 난수(`RandomNumberGenerator`)·Fisher–Yates 셔플 보드 생성·브로드캐스트 순서로 진행하며, 각 클라이언트가 가로줄 충돌·상품 구성·전원 결과(`Outcomes`) 일관성을 검증한다(Commit-Reveal 및 중앙 서버 미사용). 하강 도착 시 결과를 개별 공개하고 유료 모드(`WagerCoins > 0`)만 정산·환불 1회 가드를 적용한다. [코인 게임 처리](../src/LabPet.Client/ViewModels/CoinGamesViewModel.Ladder.cs), [사다리 엔진](../src/LabPet.Client/Games/LabLadderEngine.cs)

## 5. GCP 실시간 중계 인증 · E2EE · 메시지 비저장 정책
정의 파일: [RemoteRelayModels.cs](../src/LabPet.Shared/Protocol/RemoteRelayModels.cs), [SocialHub.cs](../src/LabPet.Server/Hubs/SocialHub.cs), [IdentityRegistryStore.cs](../src/LabPet.Server/Storage/IdentityRegistryStore.cs), [GcpSignalRTransport.cs](../src/LabPet.Client/Network/GcpSignalRTransport.cs), [HybridTransportRouter.cs](../src/LabPet.Client/Network/HybridTransportRouter.cs)
- **기기 ECDSA P-256 챌린지-응답 인증**: 클라이언트는 `%AppData%\LabPet\device_identity.json`(개인키 DPAPI 보호)에 저장된 기기 ECDSA 키쌍으로 `/api/auth/challenge`의 1회용 논스(TTL 60초)에 서명해 `/api/auth/token`으로부터 HMAC-SHA256 단기 Bearer 토큰을 발급받는다. 동일 `PetId`에 다른 공개키로 접속하려는 사칭 시도는 `403 Forbidden`으로 차단한다.
- **최소 영속 데이터 범위 및 메시지 비저장**: 서버는 `/var/lib/labpet/registry.json`에 `PetId ↔ PublicKey` 바인딩 및 승인된 상호 친구 관계만 최소 저장하며(`SaveAtomicLocked` 저장 성공/실패 반환 및 오류 로깅), **채팅 메시지 본문·빠른 반응·게임 페이로드·오프라인 쪽지는 디스크/메모리 큐/DB 어디에도 저장하지 않는다.** 수신자 오프라인 시 즉시 `RECIPIENT_OFFLINE`을 반환하고 폐기한다.
- **친구 신청·수락 멱등성 및 오류 전파**: [PendingFriendRequestStore.cs](../src/LabPet.Server/Services/PendingFriendRequestStore.cs)는 만료 툼스톤과 승인 완료(`MarkApproved`) 상태를 구분해 만료(`PAIRING_REQUEST_EXPIRED`)와 미존재(`PAIRING_REQUEST_UNKNOWN`)를 분리 반환하며, 수락 ACK 유실 시 TTL 내 수락자 재시도를 허용해 양측 동일 친구 키를 보장한다. [SocialHub.cs](../src/LabPet.Server/Hubs/SocialHub.cs)는 신청·수락·거절·ACK·친구 등록 단계마다 요청 ID·단계·오류 코드·처리 시간만 구조화 로그로 기록한다(메시지 본문·토큰·개인키·ECDH 비밀값·친구 키 비노출).
- **클라이언트 단계별 결과·오류 전파 및 로컬 저장 일관성**: [FriendOperationModels.cs](../src/LabPet.Shared/Transport/FriendOperationModels.cs), [ISocialTransport.cs](../src/LabPet.Shared/Transport/ISocialTransport.cs), [SocialCoordinatorService.cs](../src/LabPet.Client/Social/SocialCoordinatorService.cs)는 신청 전송·원격 수신·ACK 검증·로컬 영속 저장 단계와 표준 오류 코드를 상위 계층으로 손실 없이 전달한다. 수락 처리 완료 전 `friends.json` 영속 저장을 직접 대기하고, 저장 실패 시 메모리 친구 목록과 전송 계층 캐시를 롤백하며 성공으로 표시하지 않는다. `GcpSignalRTransport`는 서버 `/health`의 `bootId` 변화로 서버 재시작을 감지해 미완료 발신 요청을 정리한다.
- **종단 간 암호화(E2EE) 및 공개 탐색 프라이버시**: HTTPS/WSS 전송 계층 보안에 더해, 비친구 온라인 피어 탐색 목록에서는 공개 프로필(`OwnerName`/`PetName`/`Appearance`/`Level`)만 노출하고 `IsMusicActive`/`IsSleeping`/`FriendCode`는 비노출(`false`/빈 값)로 마스킹한다. 친구 제어 패킷은 기존 P-256 ECDH로 합의한 `PairSecretBase64`로 클라이언트 측에서 `AES-256-GCM + HMAC-SHA256` 암호화·서명한 뒤(`IsEncrypted = true`) 중계한다. 서버는 `AreMutualFriends`와 `SenderPetId == 인증된 PetId`, 크기/레이트 리밋, `MessageId` 중복만 검증하고 평문을 열람·저장하지 않는다.
- **하이브리드 경로 선택 및 중복 방지**: `HybridTransportRouter`는 LAN 온라인 피어에 대해 LAN P2P를 우선 사용하고 일시적 실패(`IsTransient`)이거나 외부 네트워크일 때만 GCP 중계로 전환하며(확정적 거부 시 불필요한 폴백 차단), LAN/GCP 간 동일 상대 중복 발신을 교차 차단한다. 양측 경로 동시 수신 시 바운디드 중복 캐시로 이벤트를 1회만 전달한다.
