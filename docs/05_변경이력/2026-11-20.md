4. 한쪽 PC에서 음악 재생 중 다른 PC에서 `[노래 따라하기]`를 켜면 3D 펫이 같은 박자로 리듬 애니메이션을 수행하고, 음악을 멈추면 약 1.5~2초 후 자동으로 로컬 모드로 복귀하는지 확인

## 버그 수정: `H.NotifyIcon.Wpf` 트레이 아이콘 `RenderTargetBitmap` 미지원 예외 수정

### 1. 변경 배경

### 2. 수정 파일 및 동작
- [PetWindow.xaml.cs](../../src/LabPet.Client/Views/PetWindow.xaml.cs): `CreateTrayIcon()`이 32x32 PNG를 표준 PNG-in-ICO 컨테이너 바이트로 감싸 `System.Drawing.Icon`을 생성하고 `TrayIcon.Icon`에 직접 할당하도록 변경

### 3. 직접 실행한 빌드·테스트 결과
- `dotnet test LabPet.slnx -c Debug`: 경고 0개, 오류 0개, 15건 통과
- `LabPet.Client.exe` 3초 런타임 기동 스모크 테스트: 크래시 없이 정상 유지 (`AliveAfter3s=True`)

### 4. 사용자 수동 확인 시나리오
1. `dotnet run --project src/LabPet.Client/LabPet.Client.csproj` 실행 시 예외 없이 바탕화면 펫 창이 뜨고 작업 표시줄 시스템 트레이에 핑크 모찌 아이콘이 표시되는지 확인

## 버그 수정: 시스템 오디오 루프백 반응 미동작 원인 수정 (`MMDevice` 조기 해제 및 `WaveFormatExtensible` 누락)

### 1. 변경 배경
실제 음악 재생 시 펫이 반응하지 않는 원인을 점검한 결과, `LoopbackAudioAnalyzer`에서 2가지 원인을 확인했습니다:
1. `TryStartCaptureLocked()`에서 `using var defaultDevice`를 사용해 캡처 시작 직후 `MMDevice` COM 객체가 즉시 해제됨
2. Windows WASAPI 공유 모드 기본 포맷인 `WaveFormatEncoding.Extensible`(32-bit Float / PCM 서브타입) 분기가 누락되어 수신 오디오 패킷이 버려짐

### 2. 수정 파일 및 동작
- [LoopbackAudioAnalyzer.cs](../../src/LabPet.Client/Audio/LoopbackAudioAnalyzer.cs): `_activeDevice` 필드로 `MMDevice` 수명을 캡처 종료 시까지 유지하도록 수정하고, `WaveFormatExtensible`(IEEE Float 32-bit, PCM 16/24/32-bit) 디코딩을 모두 지원하도록 보강

### 3. 직접 실행한 빌드·테스트 결과

## 버그 수정: 음악 내 잔잔한 구간 · 곡 전환 · 잠시 일시정지 시 음악 상태 및 노래 따라하기가 즉시 끊기는 문제 수정

### 1. 변경 배경
- 기존에는 `LoopbackAudioAnalyzer`가 순시 오디오 에너지만으로 `IsMusicActive`를 판정하여 노래 중간의 짧은 정적에도 `🎵 음악 재생 중` 상태가 즉시 꺼졌다 켜지며 깜빡거렸습니다.
- 또한 `ProtocolConstants.MusicHostSilenceTimeoutMs = 2000`(2초) 및 `MusicFrameTimeoutMs = 1500`(1.5초)으로 설정되어 있어, 호스트가 노래를 잠깐 일시정지하거나 다음 곡으로 넘어갈 때 2초 만에 노래 따라하기 구독이 자동 종료되었습니다.

### 2. 수정 파일 및 동작
- [LoopbackAudioAnalyzer.cs](../../src/LabPet.Client/Audio/LoopbackAudioAnalyzer.cs):
  - 음악 에너지가 감지된 마지막 시각(`_lastMusicEnergyTicks`)을 기록하고 `MusicActiveHoldDurationMs = 15_000.0`(15초) 동안 `IsMusicActive` 프레즌스 상태를 유지하도록 개선했습니다. (단, Bass/Mid/Treble 스펙트럼 값 자체는 기존처럼 120ms 후 0으로 감쇠되어 소리가 멈춘 동안 펫은 대기 호흡을 수행합니다.)
- [ProtocolConstants.cs](../../src/LabPet.Shared/Protocol/ProtocolConstants.cs):
  - `MusicHostSilenceTimeoutMs`를 `2000`에서 `180_000`(3분)으로, `MusicFrameTimeoutMs`를 `1500`에서 `15_000`(15초)으로 완화했습니다.
- [SocialCoordinatorService.cs](../../src/LabPet.Client/Social/SocialCoordinatorService.cs):
  - 호스트가 일시정지하거나 곡이 넘어가는 동안 팔로우 연결을 끊지 않고 대기 호흡 상태로 유지하다가 음악이 다시 재생되면 즉시 이어서 춤추도록 개선했습니다.
  - 실제 타임아웃(3분 완전 무음 또는 15초 패킷 미수신)으로 해제될 때는 호스트에도 `SetMusicFollowAsync(..., enable: false)`를 전송해 구독 목록을 함께 정리합니다.

### 3. 직접 실행한 빌드·테스트 결과
- `dotnet build LabPet.slnx -c Release; dotnet test LabPet.slnx -c Release --no-build`: 경고 0개, 오류 0개, `LabPet.Tests` 16건 실행 / 16건 통과

### 4. 사용자 수동 확인 시나리오

## 보안 강화: 친구 전용 패킷 AES-256-GCM 암호화 전송(프로토콜 v2) 및 `friends.json` 비밀키 Windows DPAPI 보호

### 1. 변경 배경
1. 기존 프로토콜 v1에서는 친구 전용 TCP 제어 패킷에 HMAC-SHA256 서명만 적용되고 `PayloadJson`이 평문으로 전송되어, 동일 LAN 내 패킷 스니핑 시 말풍선 메시지 본문과 코인 게임 선택값이 노출될 수 있었습니다.
2. `%AppData%\LabPet\friends.json`에 친구 간 공유 비밀키(`pairSecretBase64`)가 평문 그대로 저장되어, 로컬 파일이 유출될 경우 친구 통신 복호화·위조 위험이 있었습니다.

### 2. 수정·생성 파일 및 동작
- **프로토콜 v2 및 AES-256-GCM 암호화 (`LabPet.Shared`)**:
  - [ProtocolConstants.cs](../../src/LabPet.Shared/Protocol/ProtocolConstants.cs): `CurrentProtocolVersion`과 `MinSupportedProtocolVersion`을 `2`로 상향(구버전 피어는 `PeerOutdated`로 업데이트 안내)하고 AES-GCM 키/Nonce/태그 길이 상수 추가
  - [Packets.cs](../../src/LabPet.Shared/Protocol/Packets.cs): `ControlPacketEnvelope`에 `IsEncrypted`, `NonceBase64`, `AuthTagBase64` 필드 추가
  - [PacketCrypto.cs](../../src/LabPet.Shared/Protocol/PacketCrypto.cs): `pairSecretBase64`에서 `HKDF-SHA256`으로 암호화 전용 32바이트 키를 도메인 분리 파생하고, 패킷별 12바이트 난수 Nonce + 패킷 헤더 AAD를 적용하는 `EncryptControlPayload` / `TryDecryptControlPayload` 구현
- **전송 계층 암호화 강제 (`LabPet.Client`)**:
  - [LanP2pTransport.cs](../../src/LabPet.Client/Network/LanP2pTransport.cs): 모든 친구 전용 제어 패킷(`BubbleMessage`, `QuickReaction`, `PetInteraction`, `MusicFollowOn`, `MusicFollowOff`, `GameEvent`)을 AES-256-GCM 암호화 + HMAC-SHA256 이중 인증으로 송수신하며, 미암호화 친구 패킷 수신 시 `ENCRYPTION_REQUIRED`, 복호화 실패 시 `DECRYPTION_FAILED`로 즉시 거부
- **로컬 비밀키 DPAPI 보호 (`LabPet.Client`)**:
  - [LocalSecretProtector.cs](../../src/LabPet.Client/Storage/LocalSecretProtector.cs): Windows 내장 `crypt32.dll` DPAPI(`CryptProtectData` / `CryptUnprotectData`, 현재 사용자 계정 전용, 추가 엔트로피 적용)로 `"dpapi:v1:..."` 형식 보호·복호화 구현

## LAN 프로토콜 v3 보안과 펫 위치 복원

### 1. 변경 배경

- 프로토콜 v2는 친구 메시지를 암호화했지만 신규 친구가 사용할 장기 공유키는 수락 패킷에 실었다. 친구 등록의 요청 연결, 재전송·ACK 검증, 탐색 정보의 신뢰 구분, 평문 백업 보호를 보강했다.
- 이전 펫 창이 모니터 전체 영역을 기준으로 위치를 복원해 작업표시줄 뒤에 일부가 가려질 수 있었다. 게임의 선택 선공개와 중복 정산 경로도 함께 수정했다.

### 2. 수정 파일 및 동작

- 일회용 확인 코드를 LAN 밖에서 전달하고 P-256 ECDH/HKDF로 확인 키와 친구 키를 파생한다. 실제 대기 요청과 인증 응답이 일치하고 양쪽 확인이 끝나야 등록한다. 친구별 재전송 기록, 요청 ID에 묶인 서명 ACK, 검증된 탐색 프레즌스, TCP 연결 제한 및 오디오 구독별 시퀀스를 추가했다. [네트워크 보안 명세](../03_네트워크_프로토콜_및_보안명세.md)
- 본 파일과 정상 백업을 DPAPI로 보호하고 읽지 못한 암호문을 보존한다. LAN은 고정 TCP 포트에 실패하면 오류를 표시한다. 방화벽은 새 규칙 쌍을 생성한 뒤 이전 규칙을 제거하고 실제 정책을 다시 확인한다. [친구 저장소](../../src/LabPet.Client/Storage/JsonAppDataStore.cs), [방화벽 등록](../../src/LabPet.Client/SystemIntegration/FirewallRegistrationService.cs)
- 가위바위보 선택 확정·공개, 타이핑 점수의 문장 기록 재계산, 사다리 참가 순서와 상품 검증을 적용했다. 정산 전에 상태를 잠그거나 닫아 반복 처리하지 않는다. [게임 흐름](../../src/LabPet.Client/ViewModels/CoinGamesViewModel.cs), [가위바위보](../../src/LabPet.Client/ViewModels/CoinGamesViewModel.Rps.cs), [타이핑](../../src/LabPet.Client/ViewModels/CoinGamesViewModel.Typing.cs), [사다리](../../src/LabPet.Client/ViewModels/CoinGamesViewModel.Ladder.cs)
- 펫 창을 모니터 작업 영역에 맞춰 복원하고 유휴 3D 갱신 간격을 늘렸다. Windows 브랜치·PR 검증을 릴리스 워크플로와 분리했다. [펫 창](../../src/LabPet.Client/Views/PetWindow.xaml.cs), [방문 펫 창](../../src/LabPet.Client/Views/VisitorPetWindow.xaml.cs), [Windows 검증](../../.github/workflows/verify.yml)

### 3. 직접 실행한 빌드·테스트 결과

- `dotnet build LabPet.slnx -c Debug --disable-build-servers -m:1`과 `dotnet test LabPet.slnx -c Debug --no-build --disable-build-servers -m:1` 통과. 빌드 경고와 오류 각 0개, `LabPet.Tests` 57건 통과. [테스트 솔루션](../../tests/LabPet.Tests/LabPet.Tests.csproj)
- 별도 Windows WPF 창 세 개에서 실제 작업 영역을 조회하고 벗어난 위치가 들어오는 것을 확인했다. GPU Tier 2에서 4초씩 두 번 계측한 결과, 16ms 타이머 구간의 프로세스 CPU 시간은 766~938ms, 32ms 타이머 구간은 359~531ms였다. 계측 전체 작업 집합은 114.3~121.5MiB였으며 프로세스에 매칭된 GPU 엔진 최대 단일 표본은 6.68%였다. 이 값은 WPF 검증 창의 표본이며 실제 LAN 앱이나 장시간 누수 측정은 아니다.
- Release `win-x64 --self-contained true` 로컬 게시가 통과했고 버전 0.1.10 실행 파일을 생성했다. 원격 릴리스를 생성하지 않았다.
- Windows에서 기존 LabPet 방화벽 규칙의 존재를 읽기 전용으로 확인했다. 실제 규칙 재등록, 2대 PC, 대량 동시 접속, 서로 다른 배율의 모니터 전환과 절전 복귀, 설치형·포터블 업데이트는 실행하지 않았다.

### 4. 사용자 수동 확인 시나리오

1. 보조 모니터 하단에 펫을 둔 상태에서 재시작한다. 작업표시줄 위의 작업 영역에 복원되는지 확인한다.
2. 같은 LAN에 있는 두 대의 Windows PC를 모두 업데이트한다. 신규 친구를 신청하고 전달받은 확인 코드로 수락한 뒤 메시지·반응·음악 따라하기를 확인한다. 가위바위보에서 양쪽이 선택하기 전에는 상대 패가 나타나지 않는지 확인한다.
3. 관리 권한이 허용된 검증용 PC에서 방화벽 재등록과 포트 충돌 안내를 확인한다. 동일 Windows 계정으로 설치형을 업데이트한 경우와 새 포터블을 실행한 경우에 기존 프로필·친구 데이터 및 자동 업데이트 안내를 확인한다.

## 수락 버튼으로 LAN 친구 연결

### 1. 변경 배경

- 친구 신청을 수락할 때 신청자와 확인 코드를 주고받고 별도 창에 입력해야 했다.

### 2. 수정 파일 및 동작

- 확인 코드 창과 입력 단계를 제거했다. 수락 버튼을 누르면 양쪽 앱이 기존 신청에 연결된 ECDH 키 합의와 서명 확인을 자동으로 진행한다. 합의된 친구 키는 각 앱에서 생성해 기존 DPAPI 저장 방식으로 저장한다. [펫 창](../../src/LabPet.Client/Views/PetWindow.xaml.cs), [LAN 친구 등록](../../src/LabPet.Client/Network/LanP2pTransport.Pairing.cs)
- 최초 등록 중 상대의 신원을 별도로 확인하는 단계가 없어 능동적 중간자 공격에 대한 방어는 제공하지 않는다. [보안 명세](../03_네트워크_프로토콜_및_보안명세.md)

### 3. 직접 실행한 빌드·테스트 결과

- `dotnet build LabPet.slnx -c Debug --disable-build-servers -m:1` 통과. 경고 0개, 오류 0개.
- `dotnet test LabPet.slnx -c Debug --no-build --disable-build-servers -m:1` 통과. `LabPet.Tests` 58건 통과. 로컬 루프백에서 수락 한 번으로 양쪽 친구 정보가 저장되고 곧바로 메시지를 보낼 수 있는지 확인했다. 실제 두 PC의 화면과 LAN 연결은 확인하지 않았다. [소셜 코디네이터 테스트](../../tests/LabPet.Tests/SocialCoordinatorTests.cs)

### 4. 사용자 수동 확인 시나리오

1. 같은 LAN에서 한쪽이 친구를 신청한다. 상대가 펫 말풍선에서 수락을 한 번 누른다.
2. 두 앱의 친구 목록에 서로 표시되고, 바로 메시지를 보낼 수 있는지 확인한다.
