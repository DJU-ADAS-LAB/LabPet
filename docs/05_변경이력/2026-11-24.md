# 2026-11-24 변경 이력

## 1. 7종 3D 캐릭터 외형 조형 개선 및 GLB 스켈레톤 애니메이션 고도화

### 1. 변경 배경
기존 `.obj` + `rig.json` 기반 파츠 계층형 애니메이션은 단순 파츠 회전과 스케일 변형 위주라 관절 연결부 실루엣과 종별 움직임 개성에 한계가 있었습니다. 이를 해결하기 위해 Blender 5.2 단계에서 7종 캐릭터의 입체 조형을 다듬고 실제 Armature 본 계층·정점 스킨 웨이트를 포함한 `.glb` 에셋으로 내보냈으며, 클라이언트 런타임에서는 투명 바탕화면 창 호환성을 지키는 범위 안에서 선택적 CPU 스키닝·2-Bone IK·임계 감쇠 스프링·9종 모션 클립을 적용했습니다.

3. 오버레이의 **`🏠`** 버튼으로 친구 펫을 바탕화면에 데려온 뒤 그 친구 펫을 좌클릭했을 때 쓰다듬기 대신 친구 펫 위에 채팅 입력창이 뜨는지, 메시지를 입력 중이거나 수신 메시지가 도착해도 말풍선과 채팅창이 서로 겹치지 않는지 확인합니다(쓰다듬기는 친구 펫 우클릭 → `👋 쓰다듬기 보내기`에서 확인).

## 7. 방문 펫 전송창 전환과 쓰다듬기 표시

### 변경 배경

여러 방문 펫의 전송창이 동시에 열릴 수 있었다. 위쪽에 다른 팝업이 있으면 전송창이 펫과 멀어졌고, 받은 쓰다듬기 알림은 해당 친구의 방문 펫이 떠 있어도 내 펫에 표시됐다.

### 수정 파일 및 동작

- 다른 방문 펫을 누르면 이전 전송창을 먼저 닫고 누른 펫의 입력창을 연다. 작성 중이던 문장은 그 펫의 창을 다시 열면 복원된다. 전송창과 말풍선은 캐릭터의 투영 위치를 기준으로 배치하며, 전송창은 위쪽이 막히면 옆이나 아래 공간을 사용한다. [방문 펫 관리](../../src/LabPet.Client/App.xaml.cs), [방문 펫 창](../../src/LabPet.Client/Views/VisitorPetWindow.xaml.cs), [팝업 배치 계산기](../../src/LabPet.Client/Views/VisitorBubblePlacementCalculator.cs)
- 보낸 쓰다듬기 알림, 받은 쓰다듬기 및 받은 빠른 반응 알림은 해당 친구의 방문 펫 위에 띄운다. 방문 펫이 없으면 내 펫 위에 표시한다. 알림 말풍선과 채팅 메시지 스택은 각자의 표시 시간을 유지한다. [친구 말풍선 라우터](../../src/LabPet.Client/ViewModels/FriendMessageRouter.cs), [소셜 코디네이터](../../src/LabPet.Client/Social/SocialCoordinatorService.cs)
- 내 펫 쓰다듬기와 친구에게 보내는 쓰다듬기는 앱 전체에서 1초 간격을 공유한다. 연속 입력이 제한되면 전송이나 새 알림이 발생하지 않는다. [소셜 코디네이터](../../src/LabPet.Client/Social/SocialCoordinatorService.cs), [내 펫 창](../../src/LabPet.Client/Views/PetWindow.xaml.cs)

### 빌드 및 테스트

- 별도 출력 경로(`--artifacts-path .artifacts/visitor-sleep-check`)에서 Debug 솔루션 빌드 경고 0개, 오류 0개. Debug 전체 테스트 180개 통과, 실패 0개, 건너뜀 0개.
- WPF 테스트에서 두 방문 펫 사이 전송창 전환, 초안 유지, 말풍선과 전송창의 물리 화면 좌표 및 친구별 알림을 확인했다. 루프백 전송 테스트에서는 1초 이내 중복 요청 제한, 1초 뒤 재전송 및 받은 쓰다듬기의 친구 식별자를 확인했다. [방문 펫 테스트](../../tests/LabPet.Tests/VisitorPetBubbleTests.cs), [소셜 테스트](../../tests/LabPet.Tests/SocialCoordinatorTests.cs)
- 실제 두 대의 PC에서 마우스로 전송과 쓰다듬기를 반복하는 수동 검증은 미실행 범위다.

### 사용자 수동 확인 시나리오

1. 방문 펫 두 마리를 가까이 배치하고 번갈아 클릭한다. 전송창은 선택한 펫에만 열리고, 원래 펫을 다시 누르면 입력했던 초안이 남아 있는지 확인한다.
2. 두 친구 중 한 친구에게 쓰다듬기를 보내거나 받는다. 그 친구 펫의 머리 위 알림과 전송창이 겹치지 않는지 확인한다. 방문 중이 아닌 친구와 주고받을 때는 내 펫 위에서 확인한다.
3. 쓰다듬기를 연달아 누르거나 오버레이와 방문 펫 메뉴를 번갈아 사용한다. 1초 안의 입력은 한 번만 적용되고 1초 뒤 다시 보낼 수 있는지 확인한다.

## 10. 가위바위보·타이핑·공동 사다리 초대 안정화

### 변경 배경

- 발신자는 전송 ACK를 받아도 상대의 초대 표시 여부를 알 수 없었다. 수신자는 방장의 코인 확인 전에 게임을 시작할 수 있었고, 발신자와 수신자는 각자의 시점부터 만료 시간을 계산했다.
- LAN과 GCP의 게임 이벤트 중복 제거는 같은 초대 패킷의 재전송까지 막았다. 온라인 목록을 비웠다가 채우는 과정에서는 끊긴 대상을 대신해 첫 온라인 친구가 선택됐다.

### 수정 파일 및 동작

- 공용 초대 상태 머신에서 발신자 UTC 만료 시각을 사용하고, 상대 앱의 등록과 시작 확인을 별도 응답으로 받는다. 같은 친구·세션·게임·참가비·만료 시각에 대한 재전송은 기존 상태에 맞춰 응답한다. 진행 중·오프라인·코인 부족·전송 실패·거절·취소·만료를 구분한다. 온라인 목록에서 선택 대상이 사라지면 선택을 비우고, 해당 친구가 돌아오면 다시 선택한다. [공용 초대 상태](../../src/LabPet.Client/ViewModels/CoinGamesViewModel.Invites.cs), [게임 화면 상태](../../src/LabPet.Client/ViewModels/CoinGamesViewModel.cs), [하이브리드 전송](../../src/LabPet.Client/Network/HybridTransportRouter.cs)

### 사용자 수동 확인 시나리오

1. 양쪽 클라이언트를 업데이트한 뒤 LAN 친구와 외부 네트워크 친구에게 차례로 초대를 보낸다. 상대의 통합 창을 닫은 경우 데스크톱 카드에서, 게임 화면을 연 경우 배너에서 수락하고 해당 게임 화면이 열리는지 확인한다.
2. 서로 동시에 초대하거나 한쪽에서 전송 후 즉시 취소한다. 안내가 표시되고 코인이 남아 있는지 확인한다. 한쪽의 코인을 참가비보다 낮추고 같은 흐름을 반복한다.
3. 초대를 받은 뒤 수락 전에 네트워크를 잠깐 끊었다가 연결한다. 제한 시간 내에는 다시 준비될 수 있고, 끝까지 복구되지 않으면 참가비가 반환되는지 확인한다. 무료 공동 사다리에서는 잔액이 유지되는지 확인한다.

## 13. 방문 펫 전송창과 수신 말풍선 배치 개선

### 변경 배경

방문 펫의 전송창과 말풍선이 주변 방문 펫의 팝업 영역을 피하도록 계산됐다. 메시지가 추가되거나 만료되면 다른 펫의 팝업까지 다시 배치했고, 카드가 화면 가장자리에서 밀리면 말풍선의 고정 꼬리가 머리를 가리키지 못했다.

### 수정 파일과 동작

- 전송창은 기존 네임태그의 물리 화면 경계를 기준으로 바로 아래 5 DIP에 표시한다. 하단 작업 영역이 부족하면 옆쪽 또는 위쪽을 사용한다. 메시지 수신·만료와 관계없이 작성 위치를 유지하며 전송 버튼과 Enter로 같은 창에서 이어서 보낼 수 있다. [방문 펫 창](../../src/LabPet.Client/Views/VisitorPetWindow.xaml.cs), [배치 계산기](../../src/LabPet.Client/Views/VisitorBubblePlacementCalculator.cs)
- 방문 펫마다 머리 위에 메시지를 최대 5개 누적하고 각 메시지의 독립 만료 시간을 유지한다. 최신 카드가 머리에 가장 가깝다. 화면 작업 영역을 기준으로 카드별 가로 위치와 `PathGeometry`의 밑변을 계산하며 화살표 끝은 머리를 향한다. 상단 공간이 부족하면 말풍선이 아래쪽에 열리고 카드 누적 순서와 화살표 방향이 함께 뒤집힌다. [방문 펫 XAML](../../src/LabPet.Client/Views/VisitorPetWindow.xaml), [배치 계산기](../../src/LabPet.Client/Views/VisitorBubblePlacementCalculator.cs)
- 서로 다른 펫의 말풍선은 겹칠 수 있다. 로컬 수신 순번으로 열려 있는 실제 말풍선 HWND를 정렬하고 전송창을 가장 위에 둔다. 위치 변경과 만료에는 새 순번을 부여하지 않는다. [앱의 방문 펫 관리](../../src/LabPet.Client/App.xaml.cs), [팝업 순서 관리](../../src/LabPet.Client/Views/VisitorPopupOrder.cs), [Win32 헬퍼](../../src/LabPet.Client/Interop/Win32WindowHelper.cs)

- 별도 출력 경로에서 `dotnet build LabPet.slnx -c Debug` 경고 0개, 오류 0개. `dotnet test LabPet.slnx -c Debug` 전체 219개 통과, 실패 0개, 건너뜀 0개. 방문 펫 스위트 21개에서 메시지 수신·개별 만료, 5개 카드 한도, 버튼·Enter 연속 전송, HWND 순서, 입력창 좌표와 포커스, 네 모서리의 카드 경계와 화살표 끝점을 검증했다. [방문 펫 회귀 테스트](../../tests/LabPet.Tests/VisitorPetBubbleTests.cs)

1. 방문 펫 두 마리를 가까이 두고 한 펫의 전송창에 문장을 입력한다. 두 친구가 번갈아 메시지를 보내거나 말풍선이 만료될 때 이름표와 전송창이 같은 위치에 있고, 겹친 말풍선 중 최신 수신 팝업이 앞에 오는지 확인한다.
2. 전송창이 열린 펫을 화면 아래쪽으로 옮긴다. 전송창이 네임태그를 피해 옆에 열리고, Enter로 전송한 뒤 같은 전송창에서 이어 쓸 수 있는지 확인한다.
3. 방문 펫을 작업 영역 네 모서리와 다른 모니터로 옮긴다. 말풍선 본체가 작업 영역 안에 표시되고 아래쪽 배치에서도 최신 카드와 화살표가 머리 쪽을 향하는지 확인한다.
