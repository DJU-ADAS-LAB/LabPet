# 2026-11-25 변경 이력

## 1. 방문 펫 메시지 수신 시 강제 종료 근본 수정 · 예외 격리 · 경량 크래시 로그 추가

### 1. 변경 배경
설치형 `LabPet.Client.exe` (`0.3.10+b71913f37906c8fb19e7bb426bc21129602b664b`) 실행 중 방문 펫이 켜진 상태에서 친구 메시지 또는 상호작용 알림이 도착하면 앱 전체가 즉시 종료되는 장애가 4차례(`2026-11-24` `22:11:43`, `23:43:03`, `23:44:05`, `23:45:06`) 재현되었습니다.

- **Windows 이벤트 로그(`.NET Runtime` ID 1026) 및 `%LocalAppData%\CrashDumps\` 4개 덤프(`508132`, `195952`, `911532`, `107300`) 공통 예외**:
  - `System.ArgumentException: 너비와 높이는 음수일 수 없습니다.`
  - 호출 스택: `System.Windows.Rect..ctor(Double, Double, Double, Double)` ← `VisitorPetWindow.GetNearestCardBounds` ← `VisitorPetWindow.LayoutBubblePopup` ← `VisitorPetWindow.<QueuePopupLayout>b__97_0`
- **근본 원인 규명**:
  1. 방문 펫 창을 열면 `App.xaml.cs`에서 `ShowVisitorBubble("놀러 왔어!", 2200)`으로 `VisitorBubblePopup`을 열었다가 2.2초 뒤 `CloseBubblePopup()`이 `VisitorBubblePopup.IsOpen = false`로 팝업을 닫습니다.
  2. WPF `Popup`이 닫힐 때 `PopupRoot`의 레이아웃이 일시 중단(`IsLayoutSuspended = true`)되어 하위 시각 트리(`VisitorBubbleSurface` → `VisitorBubbleContent` → `VisitorStatusBubble` / `VisitorChatCards`)의 이후 수동 `Measure(...)` 호출을 건너뜁니다.
  3. 그 뒤 친구 채팅 메시지가 도착하면 `LayoutBubblePopup()`이 `VisitorBubblePopup.IsOpen == false`인 상태에서 `VisitorBubbleContent.InvalidateMeasure(); VisitorBubbleContent.Measure(Infinity);`를 먼저 실행했습니다. 이 때문에 `VisitorBubbleContent.DesiredSize`에는 이전 상태 문구(`"놀러 왔어!"`)의 크기(`72×27`)만 남아 있고, 새로 추가된 채팅 카드 `Border`는 미측정 상태(`DesiredSize = 0×0`)로 남았습니다.
  4. 이어서 `GetNearestCardBounds`가 `(card.DesiredSize.Height - 4) * scaleY < 0`인 음수 높이로 `new Rect(x, y, width, height)`를 생성하면서 처리되지 않은 `ArgumentException`이 WPF `Dispatcher`로 전파되어 프로세스 전체가 종료되었습니다.
- **동반 결함**:
  - `DockPanel`만 `InvalidateMeasure()`해 자식 카드 텍스트 변경 시 이전 측정 캐시가 남는 문제, `IsBelowHead` 반전 재측정 후 `natural`·`placement` 미갱신, `Rect.Intersect` 빈 결과(`Rect.Empty`, `-Infinity`), `Math.Clamp` 경계 역전 및 `NaN`/`Infinity` 미방어, `PresentationSource` 미연결 상태 `PointToScreen` 호출 가능성, 백그라운드 만료와 `Items` 동시 접근, frozen `TranslateTransform` 수정 가능성, Win32 HWND(`IsWindow`)·`HwndSource.IsDisposed` 미검증, `Dispatcher` 예외 격리 및 로컬 크래시 로그 부재를 함께 해결했습니다.

### 4. 사용자 수동 확인 시나리오
1. `dotnet run --project src/LabPet.Client/LabPet.Client.csproj -c Release`로 개발 빌드를 실행한 뒤 온라인 친구의 방문 펫을 바탕화면으로 데려옵니다.
2. 처음 표시되는 `"놀러 왔어!"` 말풍선이 사라진 뒤(팝업 닫힘 완료 후) 상대방 PC 또는 두 번째 클라이언트에서 짧은 메시지, 긴 자동 줄바꿈 메시지, 연속 6개 이상의 메시지, 그리고 우클릭 `👋 인사하기 보내기`를 순차 전송해 강제 종료 없이 말풍선·화살표·하단 전송창이 정상 동작하는지 확인합니다.
3. 바탕화면 상·하·좌·우 가장자리와 보조 모니터로 방문 펫을 드래그한 상태에서 메시지를 수신하고, `배율(50~150%)`을 변경해도 말풍선 방향·정렬이 유지되는지 확인합니다.
4. 예외 상황이 없다면 `%AppData%\LabPet\logs\crash.log` 파일이 생성되지 않으며, 문제 발생 시 해당 경로에서 전체 예외 스택을 확인할 수 있습니다.
