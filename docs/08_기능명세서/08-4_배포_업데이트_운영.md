# 08-4. 배포 · 자동 업데이트 · 운영 기능명세

클라이언트 배포에는 [난독화 스크립트](../../tools/obfuscation/Protect-LabPetRelease.ps1)를 적용한다. 게시 이후와 패키징 이전에 검증·정산 메서드를 난독화하고, `Mapping.txt`와 원본 `.pdb`는 Actions 아티팩트(`labpet-symbols-v<버전>`)로 보관하며 변환된 DLL로 전체 회귀 테스트를 실행한다.

## FT-11: Velopack 진입점 및 `UpdateService` (차분 자동 업데이트)
- **구현 파일**: [Program.cs](../../src/LabPet.Client/Program.cs), [UpdateSourceOptions.cs](../../src/LabPet.Client/Updates/UpdateSourceOptions.cs), [UpdateService.cs](../../src/LabPet.Client/Updates/UpdateService.cs)
- **동작 규칙**: WPF 초기화 전 `VelopackApp.Build().Run()` 호출, 시작 8초 후·5분 주기·LAN 상위 버전 감지·수동 확인(펫 우클릭 및 트레이 메뉴) 시 `SimpleWebSource`(기본) 또는 `GithubSource`에서 차분 업데이트 다운로드. Windows 부팅 자동 실행(`--autostart`) 시에는 무인 자동 재시작 적용, 일반 실행 중에는 펫 위 말풍선(`[업데이트 / 나중에]`) 표시

## FT-12: GitHub Actions 경량화 배포, 시작 프로그램·방화벽 자동 등록

- `main` 푸시와 대상 PR에서는 [Windows 검증 워크플로](../../.github/workflows/verify.yml)가 `Release` 빌드와 전체 단위 테스트만 수행한다.
- 방화벽 등록은 실행 파일 경로를 요구한다. 새 UDP·TCP 규칙을 모두 생성한 뒤 이전 규칙을 제거하고, 경로·서브넷·포트·프로토콜·방향·활성화·허용을 확인한다. [방화벽 등록 서비스](../../src/LabPet.Client/SystemIntegration/FirewallRegistrationService.cs)
- **구현 파일**: [release.yml](../../.github/workflows/release.yml), [verify.yml](../../.github/workflows/verify.yml), [StartupRegistrationService.cs](../../src/LabPet.Client/SystemIntegration/StartupRegistrationService.cs), [FirewallRegistrationService.cs](../../src/LabPet.Client/SystemIntegration/FirewallRegistrationService.cs), [SettingsPageView.xaml.cs](../../src/LabPet.Client/Views/Hub/Pages/SettingsPageView.xaml.cs), [AboutPageView.xaml.cs](../../src/LabPet.Client/Views/Hub/Pages/AboutPageView.xaml.cs)
- **동작 규칙**: 실제 배포는 `v*.*.*` 태그 푸시 시 [릴리스 워크플로](../../.github/workflows/release.yml) 단일 워크플로에서 수행한다. `LabPet.Client.csproj`에서 버전과 `Velopack` 버전을 읽어 태그와 대조한 뒤 `Release` 빌드·테스트, `win-x64` self-contained Publish, `vpk download github`, 단일 `vpk pack`(이전 릴리스 없음 또는 차분 생성 실패 시에만 전체 패키지로 대체), `vpk upload github --publish` 순으로 공식 CLI만으로 배포한다. 시작 프로그램 `--autostart`와 로컬 서브넷의 프로그램 제한 방화벽 규칙(UDP 45678~45679, TCP 45680)을 유지한다.
