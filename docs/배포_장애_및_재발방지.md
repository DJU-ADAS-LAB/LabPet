## 패키징 및 공개 예방 규칙

### v0.3.10 공개 전 자산 목록 검증 및 태그 생성 인자 바인딩

- 단계는 대상 태그 생성 전 GitHub API 자산 조회였다. 기존 정식 릴리스의 자산 여섯 개를 조회했으나 PowerShell에서 목록 개수가 `1`로 읽혔다.
- REST 명령이 배열을 단일 출력으로 전달한 결과였다. 공통 호출에서 응답을 변수로 받은 뒤 반환해 배열 응답을 개별 항목으로 전달한다.
- 실제 GitHub 자산 응답에서 파일명, 업로드 상태와 해시를 항목별로 검사한다. 초안과 공개 릴리스 확인에 같은 호출을 사용한다.
- `Release.ps1`의 `Get-LabPetGit tag -a ...` 호출에서는 고급 함수 파라미터 이름 `-Arguments`와 git `-a` 축약이 충돌해 `A positional parameter cannot be found that accepts argument 'tag'` 오류가 발생했다. `Get-LabPetGit`가 `param([Parameter(...)]$Arguments)` 대신 `$args`를 직접 전달하도록 수정했다(`scripts/Common.ps1`, 이후 파이프라인 경량화로 삭제됨).

수집한 위 원격 실패는 테스트 단계에서 패키징을 중단했다. 현재는 커스텀 스크립트(`scripts/BuildPackage.ps1`, `scripts/Release.ps1` — 삭제됨)와 자체 GitHub API 업로드를 제거하고, 단일 [릴리스 워크플로](../.github/workflows/release.yml)에서 공식 `vpk download github` → 단일 `vpk pack`(차분 불가 시 전체 패키지 폴백) → `vpk upload github --publish` 흐름으로 현재 릴리스 파일과 정적 피드(`releases.win.json` · `RELEASES`)를 원자적 초안 업로드 후 공개한다. [배포 운영 가이드](배포_운영_가이드.md)



### v0.3.13 Windows 릴리스 테스트 중단

- GitHub Actions Windows 러너에서 컴파일 오류 없이 테스트 364개가 통과하고 4개가 실패했다. 릴리스 업로드 단계는 건너뛰었다. [v0.3.13 실행](https://github.com/DJU-ADAS-LAB/LabPet/actions/runs/45556021095)
- 눈덩이 3회·10회 테스트에서 `Assert.InRange`가 허용한 0.01픽셀에 비해 화면 변환 결과가 0.08픽셀 차이 났다. 모니터의 둘레 위치가 소수 물리 좌표인 경우 Win32 화면 좌표가 반올림된다. 테스트가 항상 소수 좌표를 사용하도록 하고 축별 반 픽셀 양자화와 독립 투척을 각각 검사한다. [눈덩이 오버레이 테스트](../tests/LabPet.Tests/SnowballOverlayWindowTests.cs)
- 1024×720 작업영역에서 오른쪽에 배치된 말풍선 본문이 레이아웃·화면 좌표 반올림 후 1픽셀 넘쳤다. 본문을 작업영역보다 1물리 픽셀 안쪽에 배치했다. 꼬리 끝점은 계속 캐릭터의 실제 머리를 사용한다. [배치 계산](../src/LabPet.Client/Views/VisitorBubblePlacementCalculator.cs), [경계 테스트](../tests/LabPet.Tests/VisitorTailTargetTests.cs)
- 반복 표시 테스트는 실제 40/60ms 타이머 만료가 배치 검증보다 먼저 일어나면 꼬리가 숨겨졌다. 테스트 시간을 직접 진행해 열기·이동·꼬리 정렬을 먼저 확인하고 상태 알림, 메시지 만료를 차례로 검증한다. [말풍선 테스트](../tests/LabPet.Tests/VisitorPetBubbleTests.cs)
- v0.3.13 태그는 보존하고 수정 버전 v0.3.14로 다시 검증한다.
