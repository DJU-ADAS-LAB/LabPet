## 패키징 및 공개 예방 규칙

### v0.3.10 공개 전 자산 목록 검증

- 단계는 대상 태그 생성 전 GitHub API 자산 조회였다. 기존 정식 릴리스의 자산 여섯 개를 조회했으나 PowerShell에서 목록 개수가 `1`로 읽혔다.
- REST 명령이 배열을 단일 출력으로 전달한 결과였다. 공통 호출에서 응답을 변수로 받은 뒤 반환해 배열 응답을 개별 항목으로 전달한다.
- 실제 GitHub 자산 응답에서 파일명, 업로드 상태와 해시를 항목별로 검사한다. 초안과 공개 릴리스 확인에 같은 호출을 사용한다.

수집한 위 원격 실패는 테스트 단계에서 패키징을 중단했다. 로컬 패키징 점검에서는 Velopack 차분 생성 시 로컬 피드에 이전 전체 패키지가 같이 들어가는 것을 확인했다. 공개 피드에는 현재 릴리스와 함께 업로드하는 파일만 남기고, 전체 피드와 레거시 피드 모두 해시를 검사한다. 이전 릴리스 단계의 문제가 있어도 별도로 검증한 전체 패키지를 공개할 수 있다. 태그 SHA의 검증 성공과 파일 업로드·해시 검증이 끝나기 전에 Release를 공개하지 않는다.
